# Field Platform Product Rails

## Purpose

Keep the MVP from drifting into common product shapes that would undermine the Field Platform architecture.

These rails are agent-facing project-control guidance while the application scaffold is being built. Promote durable product context into a more specific product authority surface after that surface exists.

## Product Identity

Field Platform is a field-orientation and participation platform.

It is not:

- a generic social network
- a chat app
- a feed
- a simple event directory
- a community operating system
- a recommendation engine

## MVP Proof

The MVP proves:

- orientation
- entry
- light continuity
- stewarded representation
- reviewable nudges and relation claims
- controlled visibility, publishing, and review basics

The MVP does not prove governance, sophisticated recommendation intelligence, a social graph, full notifications, payments, federation, or complex community operations.

## First Slice Bias

The first product slice should not be events CRUD.

Prefer a public community orientation page that exercises:

- community representation
- visibility, publication, and review state
- ways-in content
- steward attribution
- one linked event or offering
- one field signal
- save, follow, or track behind auth
- relation or nudge proposal path

## Product Gravity Risks

Avoid starter patterns, UI kits, provider features, or seed data that silently imply:

- feed/follow/DM mechanics
- direct user edits to stewarded representations
- event listing as the core product
- provider-owned organization roles as product authority
- recommendation engine behavior before real evidence exists
- hidden ontology decisions in mock or seed data
