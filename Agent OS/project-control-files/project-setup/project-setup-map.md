# Project Setup Map

## Purpose

Route agents to Field Platform project setup guidance without turning this map into a long decision document.

Load this map for architecture-shaping, schema, feature, boundary, testing, deployment, or structural-maintenance tasks. Then load only the adjacent file or existing project-control file that matches the task.

## Lookup

| Need | Load |
|---|---|
| How the base Agent OS is woven into this project | `project-weaving.md` |
| Accepted stack and app architecture | `stack-architecture.md` and `../technology-architecture-map.md` |
| Product identity and MVP guardrails | `product-rails.md` and `../field-platform-product-rails.md` |
| Domain separations and authority rules | `domain-rails.md` and `../field-platform-domain-rails.md` |
| Visibility, publication, and review states | `visibility-review-publication-model.md` |
| Relation claims and nudges | `relation-claims-model.md` |
| Database and data-model rails | `data-model-rails.md` |
| Testing expectations | `testing-rails.md` |
| Local and deployable environment rails | `deployment-rails.md` |
| Generated project evidence and freshness | `generated-evidence-rules.md` |

## Rules

- This map routes; adjacent files carry the project-specific content.
- Existing project-control files remain valid setup memory until a later human-initiated maintenance task retires or promotes them.
- Generated project indexes are evidence. They do not replace source files, project-control rails, task modes, structural-maintenance behavior, or human decisions.
