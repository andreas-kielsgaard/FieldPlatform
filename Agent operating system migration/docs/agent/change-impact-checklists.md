# Change Impact Checklists

## Domain Concept Change

- Glossary.
- Naming index.
- Data model.
- Schema.
- Validators.
- Accessors.
- Routes.
- UI labels.
- Mocks.
- Tests.
- Decisions.

## Shared Component Change

- Component registry.
- Design-system map.
- Stories or examples.
- Consumers.
- Tests.
- Visual checks.
- Debt or experiment ledgers.

## Permission Change

- Policy predicates.
- Accessors.
- Guarded screens or components.
- Tests.
- Permissions and visibility map.
- Raw-literal checks.

## Route Or Page Change

- Routing map.
- Policy or visibility requirements.
- Page shell and shared primitives.
- Data accessors.
- URL state.
- Tests or flow checks.

## Mock Data Change

- Mock-data map.
- Domain glossary.
- Naming index.
- Schema or validation assumptions.
- Stories, examples, and tests.
- Known realism caveats.

## Refactor

- Agent OS map when operating-system routing changes.
- Source-directory map query when source-tree structure matters.
- Structural indexes.
- Dependency graph.
- Tests.
- Decision log if a convention changed.
- Known debt if work is partial.

## Update Rules

- Update when a recurring review miss appears.
- Update when a new task family needs explicit impact checks.
- Keep each checklist short enough to use during real work.
