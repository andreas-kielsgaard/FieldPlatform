# semantic-chunk-index

Legacy inactive: retained for the retired Agent OS generated index/query pipeline. Do not use for ordinary development; use only when an explicit legacy Agent OS index/tool maintenance task calls for it.


Deterministic Phase 3 semantic substrate with Phase 4 freshness and contract hardening.

Use this when fuzzy recall, near-match discovery, broad source orientation, reuse evidence, or rename candidates would benefit from bounded text chunks.

Builder:

```powershell
npx --yes tsx tool-implementations/semantic/build-semantic-chunk-index.ts --json
```

Check:

```powershell
npx --yes tsx tool-implementations/semantic/build-semantic-chunk-index.ts --check --json
```

Artifact:

- `tool-maintained-files/semantic/semantic-chunk-index.json`

Boundaries:

- Chunk records are query-only and should not be loaded wholesale at boot.
- Embeddings and vector stores are not generated by this artifact.
- Chunk boundaries are mechanical; use retrieved chunks as candidates, then verify against source.
- Generated chunk metadata is builder-owned and should not be hand-maintained.
- Contract validation should fail if the artifact loses schema v2 metadata, builder-owned maintenance fields, bounded chunk fields, or explicit no-embedding/no-vector status.
